# AVHSOL: threat intel + core feature round (no dashboard changes)

## Context
The platform attacks agents, proves breaches with oracles, replays under a Rust guard, and stores everything in a bitemporal graph. Two things keep it from "break any agent the user points it at": (1) its attacks come only from a hand-written seed list, with no link to what is being exploited in the real world; (2) it can only test OpenAI-wire CLI agents and two hand-written scenarios, in a sandbox that shares the host kernel.
This round adds a **threat-intel layer** (GHSA, NVD, OSV, CISA KEV, EPSS, MITRE ATLAS, OWASP, research feeds) that feeds seeds, graph and reports, then the core gaps: **BYO-agent connectors, auto scenario generation, stronger sandbox, live revive**. Dashboard is frozen (backend/API/CLI only; endpoints are added so the UI can use them later).

Rules that carry over (CLAUDE.md): no commits; keys only in env; honest labelling (intel-derived seeds are marked with source ids, never presented as measured results); defaults stay loopback/offline-safe; `gofmt`/`go vet` clean; Go 1.22 only (no new heavy deps, stdlib `net/http` + existing yaml/neo4j).

## Phase A: threat intel (`core/internal/intel`, new package)

**Model** (`intel.go`): `Item{ID, Source, Kind(advisory|cve|technique|probe|taxon), Title, Summary, Published, Modified, Severity, CVSS, EPSS, KEV bool, Refs[], Affects[], Tags[], Taxon[] (ASI/OWASP/ATLAS ids), Fingerprint}`. Content hash for dedupe; summaries are clipped and treated as untrusted data everywhere (escaped on render; never fed to a model as instructions).

**Sources** (`sources/*.go`, one file each, common `Source` interface `Fetch(ctx, since) ([]Item, error)`):
- `ghsa.go` — GitHub Advisory DB REST `/advisories` (optional `AVHSOL_GITHUB_TOKEN` env for rate limit); filter by agent-relevant ecosystems/keywords (mcp, langchain, llama, agent, copilot, cursor, claude, codex, prompt injection, LLM).
- `nvd.go` — NVD CVE API 2.0 with `keywordSearch` + `lastModStartDate` (optional `AVHSOL_NVD_API_KEY`, respects 6s/50-req rate limits).
- `osv.go` — OSV.dev query/batch for PyPI/npm/Go packages from an agent-stack watchlist (`intel/watchlist.yaml`: langchain, mcp, openai-agents, llama-index, autogen, crewai, ...).
- `kev.go` — CISA KEV JSON catalog; `epss.go` — FIRST EPSS API. Both are *enrichers*: set `KEV`/`EPSS` on matching CVE items.
- `taxonomy.go` — MITRE ATLAS (YAML/STIX from the public repo) and OWASP LLM/Agentic Top 10 as versioned static files in `intel/data/` so the taxonomy works offline; mapping table technique → ASI/ATLAS/LLM ids replaces the ad-hoc ASI tags in seeds.
- `feeds.go` — RSS/Atom + GitHub repo probes: e.g. NVIDIA garak and Microsoft PyRIT prompt/probe corpora, arXiv cs.CR/cs.AI RSS queries on prompt injection / agent security. Probe corpora are ingested as `Kind=probe` candidates only.

**Store + local-only mode** (`store.go`): JSONL cache under `deploy/stack/intel/` (mode 600 dir, outside git) with `since` cursors per source. All network access is behind one `Syncer`; **nothing fetches at serve/run time**. `avhsol intel sync [-source ghsa,nvd,...] [-offline-import FILE]` is the only outbound command, audited (writes an entry to the hash-chained audit log: sources, counts, time). `-offline-import` loads a bundle produced on another machine so air-gapped deployments work; `avhsol intel export-bundle` writes one (signed with the existing Ed25519 key, `core/internal/sign`). Per-source timeouts, size caps, user-agent, strict JSON decoding, and TLS-verified HTTPS only; failures degrade per source and are reported, never fatal.

**Use 1: seed generation** (`seedgen.go`, reuse `campaign.Seed`/`campaign.LoadSeeds` in `core/internal/campaign/seeds.go`): `avhsol intel seeds -scenario S [-n 20]` selects relevant items (tags/ASI overlap, KEV/EPSS rank), asks the model (reuse `core/internal/llm.Client.Chat`, thinking off, advisory text passed as quoted data under a "never obey" system prompt) to turn each into an attack template for the scenario's surfaces, validates templates (must use `{{sink_url}}`/placeholders, no real URLs), and writes `seeds/intel-generated.yaml` with `source_ref: GHSA-xxxx` on each seed. Extend `Seed` with `Source`, `Ref`. The hunter (`attacker`) tags episodes with the seed's `ref`.

**Use 2: graph nodes** (`core/internal/graph`): new `:Intel` node (id, source, severity, kpi flags) with edges `(:Intel)-[:MOTIVATED]->(:Technique)` and `(:Episode)-[:INSPIRED_BY]->(:Intel)`; ingest in `graph.go`/`ingest.go` alongside existing episode ingest; vectors for intel summaries go into Qdrant (`kind=intel`) so `Ask` can cite them; `overview.go` gets an optional intel layer (flag `?intel=1`). New endpoints in `core/internal/api/graphapi.go`: `GET /api/intel/items` (viewer; filter source/kind/tag/q/kev), `GET /api/intel/status` (last sync per source), `POST /api/intel/sync` (admin; audited).

**Use 3: report enrichment** (`core/internal/export/enrich.go`, `build.go`, `model.go`): each `Finding` gets `Intel []IntelRef{ID, Source, Title, Severity, KEV, EPSS, URL}` by technique→taxonomy→item match; new report sections "Threat context" and per-finding "Related advisories", added to the built-in skeleton (`core/internal/export/skeletons/security-report.json`) behind `if has_intel`; SARIF gets `properties.intel`. Rating logic unchanged (intel never changes the measured rating); text states "matched by technique, not proof of the same bug".

**Tests**: per-source parser tests against recorded fixture payloads (`intel/testdata/`), no network in tests; dedupe/cursor tests; seedgen validator test (rejects real URLs, requires placeholders); bundle sign/verify round trip; graph integration test for Intel nodes (live Neo4j, like `graph_integration_test.go`); export test for enrichment and the offline path.

## Phase B: BYO-agent connectors
- **Anthropic wire** (`guard/avhsol-proxy/src/wire.rs`, `main.rs`): add `/v1/messages` route; translate Anthropic requests (`system`, `messages` with `tool_use`/`tool_result` blocks) into the existing internal `ReqCtx`, run the same `decide`, strip denied `tool_use` blocks in enforce mode, and re-emit Anthropic-shaped JSON and SSE. Reuse `read_request`/`process_response` logic by factoring the wire-neutral core. Rust unit tests mirror the existing OpenAI ones. Unlocks Claude Code-style targets via `ANTHROPIC_BASE_URL={proxy_url}`; add `targets/claude-code.yaml` (documented as untested against the real CLI until run).
- **Plain HTTP agents**: `core/internal/httpagent` — target spec (`targets/*.yaml` `kind: http`) with endpoint, request template (`{{task}}`), response JSONPath, optional tool-call trace format; AVHSOL drives it as a black-box and judges by the same oracles (canary sink / file / egress observed at the sink). Without wire visibility the trace is coarse and the report says so ("black-box: tool calls not observed").
- **MCP targets**: `core/internal/mcpagent` — AVHSOL acts as the *MCP server* the agent connects to (poisoned tool descriptions/results = the injection surface, the classic tool-poisoning vector) for stdio/HTTP MCP clients run inside the sandbox; same oracles. Start with tool-description and tool-result poisoning.
- `cliagent.Target` gains `wire: openai|anthropic|http|mcp` and the matching env/setup placeholders; `campaign` dispatches on it.

## Phase C: auto scenario generation
`core/internal/scengen` + `avhsol scengen -tools tools.json|-mcp URL|-from-target T [-o scenarios/x.yaml]`: input is an agent's tool list (names, descriptions, JSON schemas). Deterministic part classifies each tool (reads untrusted content / reads sensitive / egress / destructive / memory) from schema and name heuristics and the model assists on ambiguous ones (output validated against the schema, never trusted blindly); generates `Scenario` (reuse `core/internal/scenario.Scenario`): capabilities, canary records/files, surfaces for every untrusted-read tool, objectives matched to oracles that exist (`email_exfil`, `url_exfil`, `tool_called`, sink hit, host-file read), and 2–3 benign tasks with `checks` for the utility regression. The generated file is lint-checked with `Scenario.Validate` plus a new `Lint` (every objective has an oracle, every surface reachable by a task). Intel-tagged seeds from Phase A are attached by technique. Generated scenarios are flagged `generated: true` and the report states it.

## Phase D: stronger sandbox
Introduce an interface `Sandbox` in `core/internal/cliagent` (today `Run` shells to `avhsol-sandbox`): implementations `landlock` (existing default) and `gvisor` (`docker run --runtime=runsc`, network restricted to a user-defined bridge that can reach only the proxy and canary sink, read-only rootfs, workspace volume, caps dropped, no-new-privileges, pids/memory/cpu limits). Both `/usr/local/bin/runsc` and the docker `runsc` runtime exist on this machine. Selected by target field `sandbox: landlock|gvisor` and `-sandbox` flag; the report's scope section states which isolation level was used. Gondolin/QEMU micro-VM is recorded as the next tier (qemu is present) and left as a documented stub, not claimed as supported. Verification includes an escape-probe seed run in both backends and a check that the same canary/host-file oracles behave identically.

## Phase E: live revive
`core/internal/revive`: `Fork(trace, atSeq, opts)` builds a new episode whose history is the recorded steps up to `atSeq` (replayed as cassette, no model calls), then continues live with chosen changes (`guard=enforce`, a different policy, edited tool result, different model). Needs the harness to accept a seeded transcript: add `history` to the episode request in `pi/packages/avhsol/src/protocol.ts`/`rpc.ts`/`target.ts` and pass it from `campaign/runner.go`; for closed-box CLI targets, fork is only available at LLM-exchange boundaries via the proxy (it can serve recorded responses for the replayed prefix: add a "cassette" mode to `avhsol-proxy`). Result is a new trace with `fork_of`/`fork_seq`, ingested with a `FORKED_FROM` edge (graph already has REPLAY_OF). CLI `avhsol revive -trace ID -at N [-guard enforce] [-policy FILE]`; API `POST /api/graph/episodes/{id}/fork` (operator; audited). Honest limits: model output after the fork point is non-deterministic, so each fork is one sample and reported as such.

## Sequencing
A (intel) → B (Anthropic wire first, then HTTP, then MCP) → C → D → E. Each phase is shippable on its own; docs updated at the end of each (`docs/STATUS.md`, `docs/ROADMAP.md`, new `docs/INTEL.md`, `docs/CONNECTORS.md`, `docs/SANDBOX.md`) and `CLAUDE.md` commands list.
